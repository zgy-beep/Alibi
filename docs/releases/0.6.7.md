# Alibi 0.6.7

Alibi 0.6.7 completes the CameraX core experience: pinch-to-zoom now works in
both photo and video modes, the photo pinch feels continuous instead of
stepping, and the viewfinder is sharper. Video recordings can start at a zoom
level chosen in the live preview, and a video stabilization setting improves
handheld recordings.

## Highlights

- **Video pinch-to-zoom (new)**:
  - The video preparation sheet now shows a persistent live viewfinder (in
    addition to the existing hold-to-peek full-screen preview) so a two-finger
    pinch is physically usable.
  - Pinch changes the camera zoom with the same frame-eased, latest-wins request
    pipeline as photo mode; the selected ratio is shown under the preview.
  - The chosen zoom ratio is carried into the recording through the start
    intent and applied to the camera before the first frame, so the recorded
    file starts at that zoom level.
- **Smoother photo pinch (no perceived latency)**:
  - The zoom target is now eased toward on a ~16 ms ticker and coalesced by
    `ZoomRequestQueue`, so at most one CameraX `setZoomRatio` request is in
    flight and the preview tracks the fingers instead of stepping per touch
    sample.
  - Absolute zoom inputs (floating overlay slider/buttons, restored zoom) still
    snap immediately; the floating overlay updates are throttled so a pinch no
    longer re-renders its controls on every frame.
  - Zoom readout moved into its own composable, so a pinch no longer recomposes
    the whole black capture screen.
  - A quick two-finger tap no longer triggers a photo capture.
- **Image quality**:
  - The photo viewfinder now requests a 1080-class preview (1440×1080 for 4:3,
    1920×1080 for 16:9) instead of CameraX's 640×480 default; if a device or
    camera extension rejects the selector, the session falls back to the
    default preview instead of failing.
  - The video viewfinder requests 1280×960 for the same reason.
  - New **video stabilization** setting (`Video settings` → quality section,
    default on) requests CameraX video stabilization only when the selected
    camera advertises support, with the setting as an escape hatch.
- **Performance**:
  - Camera bindings for the video preview live in a plain holder instead of
    Compose state, so the zoom indicator no longer causes camera rebinds.
  - Video preview bindings are keyed by lens instead of by `CameraSelector`
    instance (which has no `equals()`), removing a rebuild-on-recomposition bug.
  - Zoom persistence stays debounced; the eased frames never touch DataStore.

## Compatibility

- Version: `0.6.7 (24)`
- Application ID: `com.zgybeep.alibi`
- Updates from `0.6.1–0.6.6` install in place (same release signing certificate)
- Minimum Android version: Android 7.0, API 24
- Target SDK: 34; compile SDK: 36; CameraX 1.5.3
- Architecture split APKs (about 30 MB each):
  - `app-arm64-v8a-release.apk` (modern 64-bit devices)
  - `app-armeabi-v7a-release.apk` (32-bit devices)
  - `app-x86_64-release.apk` (64-bit emulators)
  - `app-x86-release.apk` (32-bit emulators)

## Known limits

- Device acceptance for this release was executed on the `Pixel9_API36`
  emulator (virtual cameras, `zoomRatioRange = [1.0, 10.0]`); the emulator
  cannot represent a physical phone's zoom feel, 90/120 Hz behavior, video
  stabilization quality or sensor resolution.
- Video stabilization is only requested when the camera reports the Camera2
  `ON` mode; devices without it simply record without stabilization.
- Video zoom during recording is not exposed in the recording screen (the
  screen intentionally shows app UI, not the camera); the zoom is chosen in the
  preparation preview before starting.
- Photo JPEG quality/resolution behavior is unchanged from 0.6.4–0.6.6
  (hardware JPEG cap, JPEG 100 in quality priority).

The release APK is signed with the dedicated Alibi release certificate.
