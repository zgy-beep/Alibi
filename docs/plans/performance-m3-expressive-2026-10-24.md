## 1. 目标和行为约定

目标：先消除已识别的主线程阻塞与会话竞争，再统一全应用的颜色、排版、形状、组件、状态、动效和无障碍；以可重复测试证明流畅度。

本轮交付报告、计划与证据。继续遵守“先不打包”：本轮不生成 APK/AAB，不安装应用。后续设备验收需要测试构建时，将其作为单独执行节点，届时遵循用户最新打包与设备授权。

保留以下功能约定：

- 应用内黑屏为可触摸的黑色页面；全黑、半透明、全显示均可点击拍照。STARTING/ERROR/STOPPING 及满载时不接收新请求。
- 单指纵向位移连续控制预览透明度，上滑逐渐显示，下滑逐渐隐藏，松手保持；不能改成一次滑动切换开关。
- 双指缩放、滑动、长按与单击互斥；长按直接回首页，返回动画不等待文件复制。
- 黑屏每次受理拍照仅震动，不显示拍摄完成文字。错误必须可理解、可退出、可重试；震动表示“已受理”，不能用来承诺已保存。
- 后台使用悬浮按钮点击拍照；通知保留运行状态及停止操作。系统权限、隐私指示和系统文件选择器由平台控制。
- 音频、视频、照片互斥及原有导入导出、目录权限、应用锁、旧设置兼容均纳入回归。
- 首页以紧凑屏三个主操作竖排为建议默认；保留参考页的品牌、缓存信息和清晰主次层级。宽屏可改自适应排列，避免固定高度挤压核心操作。布局最终由组件样例和尺寸矩阵验收。

## 3. 统一设计规范

### 3.1 主题和颜色

在 `ui/theme` 建立统一入口：主题配置、颜色、Typography、Shapes、Motion、Dimensions 和组件状态样例。

- 支持跟随系统/浅色/暗色；Android 12+ 动态色可开关；较低版本回退品牌色。新增设置字段有默认值，不重置现有配置。
- 使用 primary/onPrimary、primaryContainer/onPrimaryContainer、surfaceContainer 系列、onSurfaceVariant、outlineVariant、error/onError 等配对语义；业务 success/warning 作为扩展角色，同时提供浅/暗模式值。
- 首页状态、存储提示、按钮、弹层和悬浮控件共用角色；所有配色实测对比度。不要通过给所有文字统一降 alpha 模拟禁用状态。
- 黑屏拍照定义专用 capture 色域：背景纯黑，预览透明度独立，提示/错误高对比。这是设计系统内明确的功能例外。
- 状态栏/导航栏及 edge-to-edge 归属统一；进入黑屏隐藏、退出恢复，旋转/后台/返回都要验证。

### 3.2 排版、图标与布局

- 明确 display/headline/title/body/label 的用途；中文使用系统回退字体，校验行高和数字基线。正文优先 ≥14sp，重要状态避免 11sp 小字；字号选择是项目规则。
- 组件使用最小高度和内容自适应，主操作触摸目标至少 48dp；字体 200% 时允许换行，避免关键操作截断。使用 start/end 间距兼容 RTL。[S03]
- 建议间距阶梯 4/8/12/16/24/32dp，紧凑页面边距 16–24dp；圆角建议 8/12/16/24/28dp 按组件角色映射。这些数值为项目候选 token，最终由样例验收，不声称全部属于官方硬性规定。
- 统一 Material Symbols 风格，按需引入 VectorDrawable；有方向性的图标处理 RTL。无需为换图标一次引入整个图标集合。[S01]
- 首页三个操作共享一个组件 API，统一图标大小、文字基线、按压反馈和焦点。录音、录像、拍照各保留自身动作含义。

### 3.3 组件状态矩阵

| 组件 | 必须覆盖的状态 | 交互规则 |
| --- | --- | --- |
| 主/次/危险按钮 | 默认、按压、键盘焦点、禁用、处理中 | 标签和尺寸稳定；忙碌不重复提交；危险操作有清晰名称 |
| 模式选择/镜头选择 | 未选、已选、禁用、设备不支持 | 使用可访问的单选语义，选中不仅依赖颜色 |
| 设置行/开关 | 开/关、禁用、不可用及原因 | 整行与开关不产生两次切换，读屏宣布当前状态 |
| 图库项 | 占位、加载、成功、丢失、无权限、错误 | 确定宽高；失败可恢复；刷新使用刷新图标与标签 |
| 拍照会话 | 初始化、可拍、受理/排队、保存、满载、失败、停止 | 可视控件和悬浮窗使用同一状态模型；全黑不逐次弹文字 |
| Dialog/Sheet | 打开、关闭、拖动、IME、错误、长内容 | 返回/遮罩关闭规则一致；危险确认不因点击透传触发快门 |
| Snackbar/提示 | 信息、成功、警告、失败 | 不抢占持续拍摄；错误具有操作入口，不只显示异常原文 |

### 3.4 动效

- 默认使用验证后的 Expressive MotionScheme；页面转场、点击反馈、内容变化分别定义 token。由封装统一入口，禁止各页面随意追加缩放/tween。
- 页面采用幅度小的位移/淡入，明确 push/pop 对称关系；移除 1.25 倍大幅整页缩放。黑屏长按退出立即开始过渡，保存收尾在后台进行。
- 手势跟手的透明度/缩放直接响应位移，不叠加造成滞后的补间动画；只在确有必要的释放收束阶段使用动画。
- 候选体验区间：控件反馈约 100–160ms、普通页面过渡约 180–240ms；spring 不以固定毫秒数定义完成，按实际 settling/可中断行为验收。
- 同一状态不重复启动悬浮动画；退后台停止无意义的无限动画。波形/脉冲不扩散到整页重组。
- 支持系统动画缩放为 0，必要时增加应用内“减少动画”；减少大幅移动/无限装饰，保留状态变化可感知性。用实测核实 Compose 和原生 View 两条路径。

### 3.5 无障碍

- 黑屏增加语义“拍照”“返回首页”动作；TalkBack/Switch Access 无需依赖原始长按/双指手势完成核心操作。可提供语义缩放/预览调节动作，不强制增加可见文字。
- 悬浮按钮提供角色、状态说明和打开菜单/停止的可访问动作；不能只给一个 contentDescription 就认为完成。
- 合并装饰性图标语义，避免重复朗读；对错误和最终保存反馈使用合适的 live region，避免每帧缩放/每次队列更新朗读轰炸。
- 校验焦点顺序、焦点恢复、键盘/D-pad、触摸目标、对比度、大字体和 RTL。普通文本 4.5:1，大文本及必要控件边界 3:1 作为项目门槛。
- 屏幕阅读器下更换手势操作方式，需形成独立脚本；不以普通触摸自动化替代无障碍验收。

## 6. 验证方案与测试门槛

### 6.1 自动化测试（无需设备部分优先）

新增测试围绕真实风险，不只复述属性：

1. 可控 dispatcher/provider：初始化等待时停止并重启，旧初始化不得绑定。
2. 可控时间：旧 5 秒停止任务不能终止新会话。
3. 保存很慢时输入持续到达：总未完成数/字节数不越预算，受理与终态对应。
4. 取消导出/写入失败不清理源文件；成功才允许 cleanup。
5. 在保存四阶段失败，恢复不覆盖成品；索引损坏保留原数据，不能静默空库。
6. 视频未完成初始化就停止/销毁，停止幂等，外部用例不被解绑。
7. 新设置向旧 JSON 兼容、导入无效值/过大数据安全失败。

JVM 测试可覆盖纯状态机/调度；真实 ContentResolver、Surface、权限、系统生命周期需要仪器测试或用户授权设备，不能用 mock 测试替代。

### 6.3 性能测量实施细节

- 后续单独准备非 debuggable、profileable、接近 release 优化的 benchmark 变体，固定版本/数据/亮度/刷新率/温度和编译模式。[S04]
- 加请求 ID 与单调时钟 trace：输入受理、待曝光、相机请求、JPEG 回调、保存提交、最终结果。不要把 CameraX 文件回调时间直接命名为传感器曝光时间。
- Macrobenchmark 收集 StartupTimingMetric/FrameTimingMetric；用 Perfetto 追主线程、RenderThread、Binder、磁盘和 FrameTimeline，JankStats 关联页面/操作。[S05]
- 60/90/120Hz 分别对应约 16.7/11.1/8.3ms 帧间隔；以设备实际 deadline 判断超时，不用固定 16ms 衡量所有设备。旧 API 缺少 frameOverrunMs 时使用可用帧时间指标并说明口径差异。
- 相同基线重复样本，报告样本数、P50/P95/P99、超时帧比例；保留原始 trace/JSON。性能录像会干扰测量，视觉录屏与正式性能轮次分开。
- 先测无额外诊断负担的基线；StrictMode/重组计数/内存分析单独运行，避免用诊断模式数字作为最终成绩。

## 7. 迁移风险与回退

| 风险 | 处理与回退 |
| --- | --- |
| Expressive 版本仍为 beta | 显式版本锁；实验 API 限于设计系统；出现阻断时切换组件实现或回退阶段 C/D，不改业务数据格式 |
| 工具链升级影响音视频/第三方 dialogs | 分阶段提交、每阶段编译和核心回归；工具链与相机库升级不捆绑 |
| 索引格式变更 | 先备份旧格式，单向迁移有校验和完成标记；失败保留旧数据，禁止清空索引作为兼容策略 |
| 预览常驻增加耗电 | A/B 测首帧/耗电；必要时采用延迟释放/按模式策略，不承诺零功耗 |
| 新动效拖慢操作 | 手势跟手直接更新、过渡可中断；减少动画降级；性能门槛不达标则取消装饰效果 |
| UI 统一改变既有操作 | 三透明度快门、长按退出、双指缩放、悬浮点击及音视频保存全量回归 |

每阶段独立小提交，保留基线记录，回退只针对本次迁移提交；不覆盖当前工作区既有修改。数据迁移回退须按格式兼容方案操作，不能仅靠 Git 回退恢复用户数据。
