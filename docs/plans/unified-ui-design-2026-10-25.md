# Alibi 统一 UI 设计与实施计划

日期：2026-10-25 · 状态：核心页面已实施，扩展验收进行中 · 对应版本：0.6.1 (18)。

配套：[当前修复验收](../reviews/repair-recheck-2026-10-25.md)、[页面设计稿](../design/unified-ui-2026-10-25.png)。本方案细化此前 M3 迁移计划；保留已实现的主题基础，不重复估算已完成工作。设计稿为静态视觉提案，不代表 App 截图或设备验收结果。

当前实现已覆盖统一布局尺寸、主题表面层级、共享标题栏/状态组件、全宽度竖排首页、单一主动作拍照准备页、共享设置分组、状态标记和悬浮快门样式。实机结果见[修复与 UI 重构验收](../reviews/repair-ui-implementation-2026-10-25.md)。第三方设置对话框、全页面字体/读屏矩阵和性能采样仍按第 8 节验收。

## 1. 设计方向与功能约束

采用 Material 3 Expressive 方向：明确主次、较大的操作区域、柔和的容器层级、清晰的状态与克制的形变。沿用 Alibi 的蓝灰主色，以暖色作低频辅助色。录音、录像、拍照使用同一套操作卡、标题栏和状态组件。

既有交互必须保留：

- 首页三个主入口竖排，同尺寸、同图标体系；宽屏也保持竖排，右侧可以展示说明或当前会话。
- 应用内黑屏拍照；后台用悬浮窗点击快门。通知承担状态和停止/返回入口，不替代悬浮快门。
- 全黑、半透明、全显示时，点击有效拍摄区域都能拍照。单指上下连续控制预览透明度；双指缩放；长按退出到首页。
- 成功拍照不显示文字、不闪屏；成功保存后再触发用户选择的短震动，失败不触发成功震动。关闭反馈时不震动。
- 保留现有短震动参数；设备支持时再调 amplitude，不把模拟器效果当作手感结论。
- 黑屏页面不放常驻标题栏或绿点。普通页面标题栏显示应用运行状态；系统隐私指示由系统控制。
- 快捷入口明确命名“后台录音”“悬浮拍照”。当前没有后台录像快捷入口；悬浮拍照是进入会话后点击拍照。

## 3. 统一设计 token

下列尺寸是项目设计决策；dp/sp 在实现中使用对应单位，设计稿像素仅作比例示意。

| 类别 | 规范 |
|---|---|
| 固定主色 | 浅色 primary `#315A73` / onPrimary `#FFFFFF`；暗色 `#99CEE0` / `#003543` |
| 基础背景 | 浅色 `#F7F9FB`，文字 `#181C1F`；暗色 `#101416`，文字 `#E1E3E6` |
| 主容器 | 浅色 `#D1E7F4` / `#0C3449`；暗色 `#164C5F` / `#D1E7F4` |
| 成功 | 浅色 `#276A49`；暗色 `#A5D9BA`，配相应扩展容器 |
| 警告/错误 | 暂停/待处理使用 warning；失败用 error；状态同时有文字或语义，不只靠颜色 |
| 黑屏 | captureBackground `#000000`；预览上的内容白色；主题切换不影响黑屏底色 |
| 表面层级 | 页面 surface；分组 surfaceContainerLow；操作卡 surfaceContainerHigh；弹层 surfaceContainerHighest |
| 间距 | 4/8/12/16/24/32；页面边距手机 20、宽屏 24；分组间 24；行内图文 16 |
| 圆角 | 小标记 8；图标底 16；分组/操作卡 24；主按钮胶囊；弹层顶部 28–32 |
| 字体 | 系统中文/西文回退；页面标题 28/36；卡片标题 18/24；正文 16/24；辅助 14/20；标签 14/20 |
| 控件 | 图标通常 24；交互目标最小 48×48；主 CTA 高至少 56；操作卡高至少 96，随字体增长 |
| 海拔 | 普通卡片 0；悬浮控件 3；弹层 3；优先靠色阶区分，不堆叠重阴影 |

动态色开启时，使用系统派生的 Material 色角色；品牌固定色只作关闭动态色后的回退。成功/警告色按浅暗色选择并验证对比度。新增设置：主题（跟随系统/浅色/暗色）、动态色（系统支持时可选）、减少动效（系统关闭动画时强制减少）。不支持动态色的系统隐藏该开关并使用固定色。

## 4. 页面布局与组件

### 首页

顶部 Alibi 标题、固定预留宽度的状态标记、48 dp 设置按钮。内容顺序：一句主说明 → 当前缓存/时长卡 → 三张竖排入口卡 → 最近记录入口。录音、录像、拍照使用相同图标底座、文本对齐、圆角和按压效果；拍照可用 primaryContainer 作视觉重点，不改变尺寸。

活动会话占用首页时显示会话卡及管理操作，不能让其他卡看起来仍可无条件抢占麦克风/相机。启动中显示禁用和进度；发生冲突给出“已有会话正在运行”和“返回会话”。不新增未实现的“所有录制全局历史”功能。

### 拍照准备

标题“拍照”；设置/照片为次操作。两个模式选项“黑屏拍照”“悬浮拍照”，附一句行为说明。下方展示镜头、抓拍策略、保存位置摘要。底部唯一主要动作随模式变化为“进入黑屏”或“开启悬浮拍照”。缺权限时优先出现所需权限卡和授权按钮；返回系统授权后重新检查，不自动多次弹窗。

相机会话已存在时展示真实状态和管理/停止操作；不能点击模式后重建无关会话或清空待保存请求。

### 拍照设置

分为“拍摄”“画面”“反馈与操作”“保存”。保留已有均衡/快速/运动抓拍、前后摄、分辨率、比例、闪光、防抖、连续对焦、镜像、网格、记忆变焦、预览、悬浮透明度和震动选项。

2–3 个短选项可用分段控件；较长文案、字体 200% 或窄屏自动切换为单选列表弹层。每行标题 + 当前值 + 可选解释；整个行可交互，避免 switch 与行同时触发两次。受硬件限制的项说明“不支持”；会话中不允许变更的项保留当前值并说明“结束拍摄后可修改”。不承诺运动模式一定消除模糊。

### 黑屏、半透明与全预览

只有同一个预览和同一个会话：预览 alpha 为 0–1，滑动直接跟手，不做拖拽后的追赶动画。滑动距离按可用内容高度归一化。阈值采用系统 touch slop；一旦认定拖拽/双指/长按，松手不再拍照。双指开始时取消长按计时；双指缩放不改变透明度。不在滑动中重绑 CameraX。

点击仅在 `canAcceptCapture` 时入队；队列有余量可连拍，满队列不伪装成功。成功保存只触发一次短震动；不显示“已拍照”文字。首次帮助只出现一次，可在设置重看。错误允许显示可恢复提示及重试/返回；STARTING 与不可用状态应避免让用户以为已经拍摄。

长按立即返回首页，保存流程由服务继续处理到完成或错误，UI 过渡不等待慢存储。TalkBack 提供“拍照”“返回首页”“预览可见度”“缩放”替代动作；辅助操作可在读屏模式显示，不能要求读屏用户只能使用双指手势。

### 悬浮快门

56 dp 触达区域，24 dp 快门图标；拖动不会拍照，长按打开动作面板。面板使用统一圆角/色阶，含“返回应用”“结束拍摄”“收起”。就绪、启动、忙碌、失败有图标/语义区别，不能只变色。动作目标保持最小 48 dp。

先保留原生 WindowManager View，通过 `OverlayStyle` 读取与 Compose 相同的颜色、字号、圆角和动效参数；避免为视觉迁移引入新的 LifecycleOwner。黑屏专用色与可读性要求优先，背景透明度保留用户设置，但须在实际桌面背景验证文字/图标可辨识。运行中主题和减弱动画变更应更新现存悬浮窗。

### 音视频运行、图库和设置

运行界面使用一块会话状态区显示类型、时长、状态；波形/视频预览占主要内容区，计时字体不随数字宽度跳动。暂停是 tonal 操作，保存是主要操作，删除使用文字危险操作并确认。保留原“保存片段/继续录制”与“结束录制”的区别，不把保存统一解释为停止。

图库统一多选工具栏、空态与图片失败占位；删除前确认数量，失败可以重试。通用设置共享分组标题、SettingRow、ModalBottomSheet、AlertDialog 和输入错误态。欢迎/权限/应用锁沿用相同按钮和排版，不绕过原权限或锁逻辑。

## 5. 状态与反馈矩阵

拟引入 `CaptureUiState`（展示层派生状态）和 `RuntimeStatus`（可区分媒体类型/阶段），替代仅用 Boolean 表达所有状态。真相来自服务，不能根据页面是否打开推断。

| 状态 | 标题栏 | 主要控件 | 黑屏/悬浮反馈 |
|---|---|---|---|
| IDLE | 不显示运行标记 | 允许开始 | 没有活动悬浮窗 |
| STARTING | “正在准备”中性色状态 | 禁止重复开始，可取消 | 不接受快门，不震动 |
| READY（相机会话） | 绿点，“相机已就绪”语义 | 按队列容量可拍 | 成功前不作成功反馈 |
| RECORDING | 绿点，“录音/录像中”语义 | 暂停/保存/结束按业务开放 | 系统前台通知保持 |
| PAUSED | 警告色暂停图标，语义“已暂停，会话仍在运行” | 继续/保存/结束 | 不把暂停标成持续采集 |
| CAPTURING/SAVING | 活动会话仍显示运行状态；纯结束保存显示“保存中” | 以实际容量决定能否连拍 | 成功保存一次短震动 |
| STOPPING | 中性色“正在结束” | 禁止重复停止/新开始 | 允许回首页，等待请求收尾 |
| ERROR | 错误图标 + 可恢复提示 | 重试/选择目录/返回 | 不给成功震动 |

标题栏标记不做无限呼吸动画，固定布局空间避免标题跳动。异常不能只吞掉返回首页；首页应收到错误原因和修复入口。

## 6. 动效与性能约束

| 场景 | 设计目标 |
|---|---|
| 按压 | 约 120 ms，轻微压缩至 0.98 + 状态层，不移动布局 |
| 状态/选择 | 约 180 ms；颜色、图标交叉淡入，避免高度抖动 |
| 页面 | 约 220 ms；轻位移 + 淡入淡出，返回方向一致 |
| 弹层 | 约 220–280 ms，跟随系统/组件手势，中断时从当前状态继续 |
| 相机透明度/变焦 | 手势直接驱动，无弹簧超调，不重建预览 |
| 减少动效 | 去掉缩放、位移和形变；无动画或短淡变；悬浮窗遵循同一规则 |

Expressive API 可用时通过 `AlibiMotion` 适配，由一处统一选择空间/效果曲线。相机、波形等持续刷新区域缩小重组范围；I/O、索引、缩略图、目录检查不得放在 UI 主线程。布局不采用持续模糊或整页高频渐变。

验收目标（待测，非本轮结果）：代表性 60 Hz 设备上，预热后每条导航路径采样至少 30 次，帧耗时 P95 ≤16.7 ms、jank <5%、无 >700 ms 冻结帧；90/120 Hz 按实际刷新周期评估。手势到可见反馈 P95 ≤100 ms。抓拍分别记录点击→接受→曝光→保存→震动，动画不得为拍摄链增加人工延时。30 分钟循环操作无崩溃/ANR；退出会话并稳定 60 秒后，不残留相机/麦克风/定时器/Activity 引用，使用 heap/trace 给出证据。

## 8. 最终验收清单

- 主题：浅/暗 × 固定/动态色；动态色至少三组壁纸色；黑屏仍为纯黑。
- 适配：320/360/412 dp 手机宽度、600/840 dp 宽屏；竖横屏、刘海/手势导航；系统字体 100/130/200%。标题/关键动作不截断，页面可滚动。
- 可访问性：普通文字对比度 ≥4.5:1，大字及关键非文本边界 ≥3:1；48 dp 触达目标；TalkBack 顺序、按钮角色、状态描述、键盘焦点；颜色不是唯一状态线索。
- 核心动作：三透明度点击、20 次连续快门、滑动/双指/长按不误拍、队列满和失败重试；每张成功保存恰好一次反馈，失败零次成功反馈。
- 服务状态：正常停止、暂停/继续、错误、保存中、快捷入口重复、运行中权限变化；标题、页面、悬浮与通知一致。
- 设置：取消不提交、确认持久化、重启恢复、旧配置兼容；运行中不可改项有原因；所有弹层跟随主题和字体。
- 性能：使用前述目标采样；保存 trace、设备信息、统计脚本和样本数，不能用编译成功或模拟器截图替代流畅度结论。
- 测试设备：默认仅明确指定且校验为模拟器的序列号；真机操作需用户明确授权；震动/画质/厂商后台限制结论必须注明实机型号和环境。

完成定义：设计 token、组件预览、全页面映射、交互测试、性能证据和残留问题表齐全；本方案不自动授权发布、版本升级或 Git 推送。
