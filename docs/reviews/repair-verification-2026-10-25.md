# 修复验收与剩余风险

## 1. 结论

本轮已修复 R01–R06 的主要代码路径，并完成 R07–R09 的针对性优化。主题与核心组件已迁移到稳定版 Material 3 1.4.0 的设计 token，首页、设置、导航、拍照准备、图库、黑屏可见控件和悬浮窗的视觉/状态规则得到统一。

代码编译、11 项 JVM 单元测试和 lint 均通过。**设备帧时间、ANR、冷热启动、物理相机延迟、OIS 和功耗仍未实测**，因此不能据此签发“全设备流畅”结论。本轮没有生成 APK/AAB，没有连接物理手机，也没有启动模拟器。

### 2.1 工具链和主题

- 工具链升级为 Gradle 8.11.1、AGP 8.9.1、Kotlin 2.0.21、`compileSdk 36` 和 Build Tools 36.1.0。
- Material 3 由原先实际解析的 1.3.0 升级到稳定版 **1.4.0**；Compose BOM 为 2025.06.01。
- 未采用需要 SDK 37 和 AGP 9.1 的 Material 3 1.5.0-beta02。完整测试版 Expressive API 仍属于后续工具链升级范围。
- 新增品牌浅/暗色、success/warning/capture 扩展色、完整排版入口、8–32dp 形状阶梯和统一动效 token。
- 设置页可实际切换系统/浅色/深色、动态色和减少动画；系统动画缩放为 0 时也使用减少动画路径。
- 页面转场改为一致的短位移加淡入；首页紧凑屏改为三张竖向模式卡；主操作按钮统一状态、形状和按压反馈。
- 黑屏保留纯黑和单次拍照仅震动；全黑、半透明、全显示继续共用点击拍照逻辑。

## 4. 尚未完成或仍需实测

1. 图库索引仍是单个 JSON 文件，能避免主线程阻塞，但大量照片时每次写入仍是全量文件。后续需事务数据库或增量日志与分页。
2. 导出失败已不删除源文件，但超大媒体的进度、取消和后台保活仍可在设备上改善。
3. 无设备数据验证点击延迟、帧超时、ANR、内存/FD 增长、温度、ZSL、OIS 和快速模式画质。
4. 稳定版 1.4.0 不提供全部 1.5 预览版 Expressive 组件；当前采用稳定库支持的语义色、形状、排版、状态和统一动效。
5. 第三方时长/列表/输入弹层继续使用原库，但继承统一 Material 主题；尚未逐个替换为原生 M3 组件。
6. TalkBack、Switch Access、200% 字体、360/411/600dp、横屏、暗色/动态色和 RTL 的最终视觉矩阵仍需设备截图验收。

## 5. 设备验收前的下一步

- 在不违反“先不打包”要求时，先建立 profileable 测试变体，按原计划测量 FrameTimingMetric、输入受理、冷启动和 30 分钟稳定性。
- 由用户明确授权具体物理设备后，验证 ZSL/OIS、悬浮窗、厂商后台限制、照片方向和实际快门手感。
- 若后续要求完整 1.5 Expressive 组件，应另立 SDK 37/AGP 9.1 工具链任务，并重新回归 CameraX、第三方弹层和音视频服务。
