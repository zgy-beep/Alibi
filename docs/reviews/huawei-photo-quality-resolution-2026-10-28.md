# 高分辨率设备画质模式分辨率修复

日期：2026-10-28 · 状态：**真机已验证** · 基线：`0.6.3 (20)` 已发布；本修复未发布 · 设备：华为 Mate 70 Pro（PLR-AL50，HarmonyOS 4.3 / Android 12）

## 问题

在 Mate 70 Pro 上实测“画质优先”：

| 配置 | 输出尺寸 | 文件大小 | 亮度量化表 |
| --- | --- | ---: | --- |
| 推荐（ZSL/硬件 JPEG） | 3072×4096（约 12.6MP） | 约 4.0 MB | JPEG 100 |
| 画质优先（软件 JPEG，0.6.3 行为） | 3264×2448（约 8.0MP） | 约 3.5 MB | JPEG 100 |
| 画质优先（硬件 JPEG，临时对照） | **6144×8192（约 50MP）** | 约 13–15 MB | JPEG 100 |

结论：CameraX 的 `setSoftwareJpegEncoderRequested(true)` 在这台设备上把画质模式限制在约 8MP，而硬件 JPEG 路径可以输出完整的 50MP 传感器画面。0.6.3 的“画质优先”在 Mate 70 Pro 上反而比“推荐”分辨率更低。

## 原因

- 0.6.3 为了在模拟器上获得确定的 JPEG 100 量化表，画质模式强制请求软件 JPEG 编码器；
- 软件编码器在高像素设备上受实现/内存限制，CameraX 选择了较小的支持尺寸（3264×2448）；
- 华为 HAL 的硬件 JPEG 本身已经输出 JPEG 100，且支持最大 6144×8192。

## 修复

- 从 Camera2 `SCALER_STREAM_CONFIGURATION_MAP` 查询当前镜头的 JPEG 最大输出像素数；
- 仅当“画质优先 + 硬件 JPEG 最大像素数 ≤ 8MP”时才请求软件 JPEG 编码器（保留模拟器上的 JPEG 100 证据路径）；
- 硬件 JPEG 上限高于 8MP 的设备（华为 Mate 70 Pro、常见 12MP/48MP/50MP 手机）改用硬件 JPEG，优先保证最大分辨率；硬件 JPEG 的质量档位由厂商 HAL 决定；
- 新增 `shouldUseSoftwareJpegEncoder()` 纯函数与 3 项单测；
- 扩展模式仍不使用软件 JPEG，避免厂商扩展与软件编码冲突。

## 验证

| 检查 | 结果 |
| --- | --- |
| 华为 Mate 70 Pro 画质优先（修复后） | **6144×8192（50MP）**，14,696,183 B JPEG，量化表 JPEG 100 |
| 华为 Mate 70 Pro 推荐 | 3072×4096（12.6MP），约 4 MB，正常 |
| 华为 Mate 70 Pro 扩展不可用回退 | 自动拍照正常，无崩溃 |
| JVM 单测 | **30 / 30**（新增 `PhotoCaptureJpegEncoderTest` 3 项） |
| Kotlin 编译 | 通过 |
| Lint | **0 error / 0 fatal**（188 既有 warning） |
| Release 构建 | `:app:assembleRelease` 通过（R8 + 签名） |

## 影响与边界

- 0.6.3 已发布包不包含此修复：华为等高像素设备的“画质优先”仍会限制到约 8MP；需要在下一版（0.6.4）发布后生效。
- 模拟器（硬件 JPEG 上限 1856×1392 = 2.58MP ≤ 8MP）仍走软件 JPEG，JPEG 100 行为不变。
- 12MP 手机硬件 JPEG 上限约 12.2MP > 8MP，将改用硬件 JPEG，保留 12MP；JPEG 质量由厂商 HAL 决定（华为实测为 100，部分设备可能为 95）。
- 高像素照片文件明显更大（华为 50MP 约 14.7MB），保存时间和存储占用增加，这是画质优先的预期代价。
- 华为的夜景/HDR CameraX 扩展仍不可用（见[相机扩展验收](camera-extensions-2026-10-28.md)），本修复只解决单帧分辨率/编码，不解决多帧降噪。
